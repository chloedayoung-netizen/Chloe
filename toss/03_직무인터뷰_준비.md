## B. 예상 질문 8개와 답할 사례 (사례 뱅크)

각 답은 **상황 1문장 → 내가 바꾼 판단 → 결과(숫자) → 토스에서는** 순서, 90초 이내.

### 1. 연간·분기 세일즈 목표를 어떻게 세우겠습니까?
- **먼저 인정**: "조직 단위로 연간 목표를 세워 본 적은 없습니다."
- **아는 것**: 핑퐁에서 첫 연락→계약 주기(약 1.5~2개월)와 단계별로 멈추는 이유를 기준으로 딜을 진행했다.
- **접근법**: 아래 C의 케이스 답(하향식 목표와 상향식 캐파시티를 맞추는 방식)으로 이어 간다.

### 2. 세일즈 생산성은 어떤 지표로 재겠습니까?
- 사례: 건 단위 로그(요청·회신·현재 상태·다음 행동). 영업 시간이 고객이 아니라 **사내 회신 대기**에 묶이는 걸 보이게 만들었다.
- 답: 활동량(통화 수)보다 ① 첫 연락 기한 준수율 ② 사내 회신 일수 ③ 1인 한도 대비 배정. 업무 샘플 2쪽 지표 트리.
- 꼬리 질문 대비: "왜 활동량을 안 보나?" → 핑퐁에서 계약을 만든 건 활동량이 아니라 맞는 계정·결정권자였다(사례 1).

### 3. 데이터로 전략을 바꾼 사례는?
- 상황: 선도 경쟁사가 채널을 선점. 기존 방식은 셀러 리스트 → 이미 결제사를 정한 셀러 → 요율 경쟁.
- 판단: "지금 결제 경로를 정하는 중인 회사"를 찾는 쪽으로. 신호 = 해외사업 채용공고·해외 진출 기사·국내 H&B 채널 랭킹, 그중 카테고리 1위만.
- 결과: 카테고리 1위 브랜드 **3곳 계약**, 아마존 카테고리 1위 판매기업 **3곳 결정권자 미팅**. 첫 연락부터 약 1.5~2개월.
- 토스에서는: 신호 가중치를 감이 아니라 분기마다 실제 전환율로 다시 맞춘다(업무 샘플 3쪽).

### 4. 만든 프로세스를 현장에 정착시킨 방법은?
- 리드 분배 스프레드시트 → **회사 전체 사용**.
- 콘센트릭스: 원본을 붙여 넣으면 담당자 16명의 서로 다른 시트 형식으로 나뉘는 수식 → **퇴사 뒤에도 동료가 사용**.
- 공통 원칙: 사용자가 입력하는 칸을 최소로. 담당자의 기존 형식을 바꾸게 하지 않고 내 쪽에서 맞췄다(16명 각자의 형식 그대로).
- 꼬리: "티켓 시스템이 당신 덕인가?" → A-1 그대로.

### 5. 이해관계자의 저항을 조정한 경험은?
- 피더블유케이: 신규 계약에만 쓰던 '선급금 50%' 조건을 기존 거래처로 넓히는 협상안 → 대표 승인 → **표준 관행**.
- 핑퐁 KYB: '소유주 전원 신분증' 규정 앞에서 "이 규정이 확인하려는 것은?"(실질 지배력)으로 질문을 바꿔 DART 공시로 대체 증빙 → 컴플라이언스가 승인 판단, **추가 서류 없이 승인**.
- 주의: 승인 판단은 컴플라이언스가 했고, 나는 판단에 필요한 자료를 먼저 준비했다고 정확히 말한다.

### 6. 분석 도구는 어디까지 다룹니까?
- 한 것: Google Sheets 수식 설계, Apps Script(KYC 단계별 발송·발송 시각 자동 기록), 정산 비교 시트(과거 공시환율·우대율로 예상 정산액), Python + Claude Code로 리서치 자동화 파이프라인.
- 안 한 것: SQL, Salesforce/HubSpot 어드민. 사실대로. `[확인 필요: 학습을 시작했다면 무엇을 어디까지]`

## C. 케이스 대비 · "토스 B2B 세일즈의 내년 계획을 세운다면?"

**답의 구조 (5분)** — 해 본 적 없는 영역이므로 "제가 이해하는 방식은 이렇고, 핑퐁에서 쌓아 본 숫자는 이것"으로 말한다.

1. **하향식 목표 확인**: 사업 계획이 요구하는 신규 매출 목표부터 받는다.
2. **상향식 캐파시티 계산**: 필요한 활성 고객 → 필요한 리드 → 필요한 인원을 지난 실적으로 역산한다.
3. **차이를 메우는 레버**: 인원 / 1인 생산성 / 단계별 전환율 / 고객당 매출. 레버마다 근거와 리스크를 붙인다.
4. **분기 배분**: 신규 인원의 램프(적응 기간)와 접수→활성 주기만큼 매출이 뒤로 밀린다는 점을 반영한다.
5. **추적 체계**: 분기마다 실제 전환율로 가정을 갱신한다(업무 샘플의 대시보드).

**숫자 예시 (전부 가상, 업무 샘플 시트의 전환율 사용)**

| 항목 | 값 | 계산 |
|---|---|---|
| 하향식 신규 매출 목표 | 120억 원 | 사업 계획(가정) |
| 고객당 연 매출 | 1억 원 | 가정 |
| 필요한 활성 고객 | 120곳 | 120억 ÷ 1억 |
| 접수 → 활성 전환 | 약 8.3% | 시트: 36건 중 3건 |
| 필요한 리드 | 약 1,440건 | 120 ÷ 0.083 |
| 숙련 1인 연간 처리 리드 | 240건 | 가정 (분기 60건) |
| 필요 인원(숙련 기준) | 6명 | 1,440 ÷ 240 |
| 현재 4명이면 | 2명 채용 + 램프 | 1분기 말 입사 · 2~3분기 50% · 4분기 100%면 신규 1인 = 0.5명분 → 실효 4 + 1 = 5.0명 → 목표의 약 83%, **17% 부족** |

**부족분을 말하는 법**: "인원만으로 채우면 상반기에 못 맞춥니다. 시트에서 가장 낮은 전환은 온보딩→활성(50%)이었으니, 여기를 60%로 올리면 같은 리드로 활성 고객이 20% 늘어납니다. 채용보다 먼저 볼 레버라고 생각합니다."
→ 숫자 자체보다 **어느 레버를 왜 먼저 보는지** 판단을 보여 주는 게 목적.

**꼬리 질문 대비**
- "전환율이 세그먼트마다 다르면?" → 세그먼트별로 따로 역산하고 합친다. 대형은 주기가 길어 하반기 매출 기여가 작다.
- "목표가 너무 높게 내려오면?" → 레버별로 필요한 개선 폭을 숫자로 보여 주고, 리더가 고를 수 있게 선택지 2~3개로 만든다(DRI에게 판단 재료를 준다).
