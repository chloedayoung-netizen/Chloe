# 캐릭터챗 MVP — 지원 전 2주 실험

문토 신사업 PO(AI 캐릭터챗) 지원을 위해 직접 기획·제작한 가장 작은 캐릭터 대화 서비스.
**질문 하나만 확인한다: 어떤 장르(설렘 / 위로 / 이야기)가 다음 날 사람을 다시 오게 하고, 돈 낼 마음을 만드는가.**

| 파일 | 역할 |
|---|---|
| `src/characters.js` | 캐릭터 3명 프롬프트, 친밀도 3단계, 기억·내일 떡밥 규칙 |
| `src/safety.js` | 위기 신호 고정 안내(모델 호출 안 함), 기억 메모 개인정보 필터 |
| `src/worker.js` | Cloudflare Worker: `/api/chat`(OpenRouter), `/api/event`(로그) |
| `public/index.html` | 로그인 없는 모바일 웹 채팅 (연령 확인, 무료 30턴, 결제 의향 창, 피드백) |
| `apps_script/Code.gs` | Google Sheets 로그 수집 + `summary` 탭 지표 자동 계산 |

## 무엇을 재미 장치로 넣었나

| 장치 | 구현 | 가설 |
|---|---|---|
| 기억 | 사용자가 말한 일상·계획을 모델이 `[[기억: …]]`로 표시 → 기기에 저장 → 다음 대화 시스템 프롬프트에 주입 | "날 기억한다"는 느낌이 재방문을 만든다 |
| 내일의 떡밥 | "오늘은 여기까지"를 누르면 캐릭터가 다음 방문 때 확인할 거리를 남김 → 다음 날 첫 화면에 표시 | 이어지는 이야기가 D1을 만든다 |
| 친밀도 | 보낸 메시지 수로 처음 → 가까워짐(15) → 단짝(50), 말투·호칭이 바뀜 | 관계가 깊어지는 단계가 계속 쓸 이유가 된다 (네이버웹툰 캐릭터챗: 친밀도형 캐릭터 유료 메시지 비중 52%) |
| 무료 한도 | 하루 30턴 무료, 넘으면 결제 의향 창 | 한도에 닿는 사람 비율 = 헤비 유저 비율 |

## 결제 의향 창은 정직하게

실제 결제는 받지 않는다. 사용자가 가격을 고르면 "아직 결제를 받지 않아요, 골라 주신 선택은 가격을 정하는 데만 써요"라고 바로 알리고 10턴을 더 준다.
가격(하루 1,900원 / 월 6,900원)은 공개 자료의 제타 패스 월 14,900원, 크랙 유료 모델 턴당 28원~ 사이에서 '첫 결제 문턱'을 낮게 잡은 가정이다.

## 안전 · 개인정보

- 만 19세 이상 확인 후 시작, AI 캐릭터임을 첫 화면에 표시
- 위기 표현(자해·자살 관련)은 모델을 부르지 않고 109 / 1577-0199 안내로 고정 응답, 로그에는 '발생'만 남김
- 대화 원문은 서버에 저장하지 않음(사용자 기기에만). 로그는 이벤트 종류·길이·비용·버튼 선택만
- 기억 메모에서 전화번호·이메일·주소 패턴은 버림
- 근거: Roblox Trust & Safety QA에서 쓰던 '규정이 막으려는 것부터 본다'는 기준, 2026년 KISO 'AI 캐릭터 챗봇 가이드라인(가안)'의 연령 확인·위기 대응·과몰입 완화 항목

## 배포 (약 20분)

1. **로그 시트**: 새 Google 스프레드시트 → 확장 프로그램 → Apps Script → `apps_script/Code.gs` 붙여넣기 → 스크립트 속성 `SHEET_TOKEN`(아무 긴 문자열) → 배포 → 웹 앱(실행: 나, 액세스: 모든 사용자) → URL 복사
2. **모델 고르기**: OpenRouter에서 후보 2~3개를 같은 첫 대화로 직접 써 보고, 한국어 말투가 자연스럽고 1회 응답 비용이 낮은 것을 `wrangler.toml`의 `MODEL`에 넣는다
3. **배포**
   ```bash
   cd munto/mvp
   npx wrangler login
   npx wrangler secret put OPENROUTER_API_KEY
   npx wrangler secret put SHEET_WEBHOOK_URL
   npx wrangler secret put SHEET_TOKEN
   npx wrangler deploy
   ```
4. 나온 `https://character-chat-mvp.<계정>.workers.dev` 로 들어가 직접 10턴 대화 → 시트 `events` 탭에 줄이 쌓이는지 확인
5. 미리보기만 할 때: `public/index.html?demo=1` (모델 없이 화면만)

로컬 확인은 `npx wrangler dev` (`.dev.vars`에 비밀값). 이 저장소에서는 가짜 모델·가짜 시트 서버로 전체 흐름(대화 → 기억 저장 → 위기 안내 → 결제 의향 → 작별 인사·떡밥 → 다음 날 표시 → 로그 15종)을 자동 테스트했다.

## 실험 운영 (2주)

**모집 링크는 경로마다 `?src=`를 다르게** 붙인다. 시트 summary에 경로별 방문·시작·D1이 따로 나온다.

| 경로 | 링크 꼬리표 | 목표 |
|---|---|---|
| 지인 | `?src=friend` | 5~8명 (첫 3일, 버그 잡기용) |
| 캐릭터챗·웹소설 커뮤니티 (규칙상 홍보 허용된 곳만) | `?src=community` | 10명 이상 |
| 스레드·인스타 게시글 | `?src=sns` | 5명 이상 |

목표 총 20~30명, 지인 아닌 사람 15명 이상. 매일 밤 summary 갱신 → 메모 한 줄.

**판정 규칙 (데이터 보기 전에 정해 둠)** — 표본이 작으므로 '방향'만 본다.

| 보는 숫자 | 기준 | 그러면 |
|---|---|---|
| 첫 메시지 시작률 | 50% 미만 | 첫 화면·캐릭터 소개 문구부터 고친다 (3일차) |
| 장르별 '이틀 이상 온 사람' | 한 장르가 다른 두 장르의 2배 이상 | 2주차는 그 장르 캐릭터만 하나 더 만든다 |
| D1 재방문 | 전체 20% 미만 | 떡밥 문구를 더 구체적으로 바꿔 프롬프트 `p2`로 재측정 |
| 무료 한도 도달 | 시작한 사람의 10% 이상 | 한도·가격을 실제 결제로 시험할 가치가 있다고 본다 |
| 결제 의향 / 한도 도달 | 30% 이상 | 하루 이용권보다 월 구독 중 무엇을 더 골랐는지로 첫 과금 구조를 정한다 |
| 세션당 AI 비용 | 하루 이용권 가격의 1/10 초과 | 모델 교체 또는 히스토리 길이 축소 |

프롬프트를 바꾸면 `index.html`의 `PROMPT_VERSION`을 `p2`, `p3`로 올린다. 로그의 `variant` 칸으로 버전 전후를 나눠 본다.

## 지원서에 쓸 때 지킬 것

- 사용자 수, 지인 수, 기간, 프롬프트 버전 수를 그대로 쓴다. "통계적으로 의미 있는 표본 아님"을 명시
- 기대와 다른 결과(예: 결제 의향 0건)도 그대로 쓰고 무엇을 바꿨는지 적는다
- 만든 범위: 기획·프롬프트·화면·로그 설계는 직접, 코드는 Claude Code와 함께 작성하고 직접 검수
